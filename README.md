# Stakeholder Intelligence Agent

Local multi-agent application for collecting stakeholder interviews and project documents, then
producing evidence-backed project-management insights.

## What the application contains

- one React 19, TypeScript, Vite, and Tailwind CSS frontend;
- one Python/LangGraph Agent Server backend with custom FastAPI routes;
- a stakeholder interview agent with SQLite checkpoint continuation;
- a Deep Agent insight workflow with separate researcher and editor subagents;
- PDF, DOCX, PPTX, XLSX, PNG, and JPEG ingestion through Docling;
- engagement-scoped hybrid retrieval with Qdrant and BGE reranking;
- local SQLite persistence and engagement-scoped artifact storage;
- Gemini for chat, vision, embeddings, schema-bound filter output, and model fallback;
- deterministic citations and source drill-down.

The application is designed for local execution. Cloud deployment, external business connectors,
web search, enterprise identity, automatic report delivery, and numerical stakeholder scoring are
not implemented.

## Prerequisites

- Windows PowerShell;
- Docker Desktop or another Docker Engine with Compose;
- Node.js compatible with `frontend/package.json`;
- network access for the initial dependency and model downloads;
- a Google API key for live Gemini calls.

## Setup

From the project directory:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1
Copy-Item .env.example .env
Push-Location .\frontend
npm.cmd ci
npm.cmd run build
Pop-Location
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-browser.ps1
```

Fill every required blank value in `.env`. Keep credentials, tokens, invitation links, databases,
runtime uploads, and generated test artifacts outside Git.

The Gemini request rate is configured in `.env`:

```env
STAKEHOLDER_AI_GEMINI_REQUESTS_PER_MINUTE_LIMIT=15
STAKEHOLDER_AI_GEMINI_REQUESTS_PER_MINUTE_HEADROOM=1
```

The effective application limit is `LIMIT - HEADROOM`, so the values above allow at most 14 Gemini
requests per minute. Set `LIMIT` to the quota of the relevant Gemini project; `HEADROOM` reserves a
small safety margin and may be set to `0` when the full configured quota should be used.

The production frontend build is served by the Agent Server from `frontend/dist/`; a separate Node
server is not part of the runtime topology.

## Run locally

Start Qdrant:

```powershell
docker compose up -d qdrant
```

Start the Agent Server:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-server.ps1
```

Open `http://127.0.0.1:2024/pm` for project-manager access. Stakeholders use the private invitation
URL generated by the project manager.

At startup, the application applies forward-only SQLite migrations and initializes the local PM
identity from `STAKEHOLDER_AI_PM_BOOTSTRAP_TOKEN`. Changing that token against an existing database
fails safely instead of silently creating a second identity.

## Synthetic demo data

The demo seed creates fictional engagements, stakeholders, interviews, supporting documents, and
insight requests through the same HTTP, Gemini, Docling, Qdrant, interview-agent, and Deep Agent
boundaries used by the frontend.

With Qdrant and the Agent Server running:

```powershell
.\.venv\Scripts\python.exe .\scripts\seed_demo_engagements.py
```

Generate or verify only the synthetic DOCX inputs without changing application data:

```powershell
.\.venv\Scripts\python.exe .\scripts\seed_demo_engagements.py --prepare-documents-only
```

The seed is idempotent for the same revision. Generated data is written beneath the configured
`STAKEHOLDER_AI_DATA_ROOT`, which is excluded from Git.

## Backend verification

Run the locked offline quality gate:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-quality.ps1
```

It checks the dependency lock, Ruff formatting and linting, strict mypy, offline pytest coverage with
an 80 percent branch-coverage floor, and Bandit.

Run the real Docling and BGE tests separately:

```powershell
.\.venv\Scripts\python.exe -m pytest tests\slow -q
```

Run the reproducible retrieval quality gate with the pinned local BGE model:

```powershell
.\.venv\Scripts\python.exe .\scripts\evaluate_retrieval.py `
  --local-files-only `
  --output .cache\retrieval-evaluation.json
```

With a configured Google API key, run the full synthetic document-to-retrieval path. This creates
temporary DOCX inputs and executes Docling extraction, course-aligned contextual chunking, real
Gemini dense embeddings, FastEmbed BM25, Qdrant-native RRF, and the mandatory BGE reranker:

```powershell
.\.venv\Scripts\python.exe .\scripts\evaluate_retrieval.py `
  --live-pipeline `
  --local-files-only `
  --output .cache\retrieval-evaluation-live.json
```

The gate reports ranking quality at top five and recall/source coverage at the production top-ten
cutoff. It fails if BGE does not preserve production coverage or improve/preserve top-five MRR and
nDCG. Evaluation outputs remain local beneath `.cache/`.

The files under `tests/fixtures/` are synthetic test inputs. They contain fictional content and
controlled canary values used to exercise the six supported formats, OCR, extraction, validation,
retrieval, and corrupt-file rejection. They are required to reproduce the test suite.
